# مقترح تصميم مبسط لشاشة الدخول واللوحة الرئيسية حسب دور المستخدم

**النظام:** BIN ZOMAH INTL. Fleet Management  
**الهدف:** تقليل الحمل المعرفي، اختصار عدد النقرات، وإظهار المهمة التالية المناسبة لدور المستخدم من دون تعديل نموذج الصلاحيات القائم.  
**إعداد:** Manus AI  

## الخلاصة

يُقترح تحويل الصفحة الرئيسية من لوحة موحدة غنية بالمؤشرات إلى **بوابة عمل موجهة بالدور**. تظهر للمستخدم ثلاثة مؤشرات كحد أقصى، وإجراء رئيسي واحد، وقائمة مهام قصيرة، وأربع مساحات عمل فقط. تبقى جميع الأقسام الأخرى قابلة للوصول من البحث أو القائمة المختصرة، لكنها لا تنافس المهمة اليومية على الشاشة الأولى.

تظل شاشة الدخول أبسط جزء في النظام. وظيفتها الوحيدة هي تمكين المستخدم من الدخول بأمان وبأقل تردد. يجب ألا تتضمن لوحة مؤشرات أو روابط تشغيلية أو حركة طويلة. يمكن الاحتفاظ بشعار WebP المتحرك كهوية قصيرة قابلة للتجاوز، ثم تظهر بطاقة دخول ثابتة ذات إجراء واحد واضح.

> **مبدأ التصميم:** لا تتغير الصلاحيات أو المسارات الخلفية. الذي يتغير هو ترتيب الأولويات، والصفحة المقصودة بعد الدخول، ودرجة ظهور كل وظيفة بحسب الدور المصرح به.

## 1. شاشة الدخول المقترحة

### البنية

| المنطقة | المحتوى | القرار التصميمي |
|---|---|---|
| الهوية | الشعار الثنائي اللغة واسم الفرع | يظهر الشعار المتحرك مرة واحدة فقط، ثم يبقى الشعار الثابت الأخف داخل البطاقة. |
| العنوان | «مرحبًا، سجّل الدخول إلى مساحة عملك» | عنوان واحد مباشر بدل وصف مطول للنظام. |
| النموذج | اسم المستخدم وكلمة المرور | حقلان فقط، مع دعم مدير كلمات المرور وإظهار أو إخفاء كلمة المرور. |
| الإجراء الأساسي | زر «تسجيل الدخول» | زر ذهبي كامل العرض؛ لا ينافسه أي زر ثانٍ. |
| المساعدة | «نسيت كلمة المرور؟» ووسيلة دعم مختصرة | رابط ثانوي منخفض البروز؛ لا تعرض أرقامًا أو تعليمات كثيرة. |
| التحكمات الثانوية | تبديل العربية والإنجليزية | يبقى في أعلى البطاقة أو خارجها، ولا يزاحم النموذج. |

### مخطط سلكي

```text
┌──────────────────────────────────────────┐
│  [الشعار الثابت]                         │
│  مرحبًا، سجّل الدخول إلى مساحة عملك       │
│  فرع الدمام · نظام إدارة الأسطول          │
│                                          │
│  اسم المستخدم                            │
│  [_______________________________]       │
│                                          │
│  كلمة المرور                    [إظهار]  │
│  [_______________________________]       │
│                                          │
│  [          تسجيل الدخول          ]      │
│  نسيت كلمة المرور؟                        │
└──────────────────────────────────────────┘
```

### سلوكيات لازمة

يظهر زر الإرسال في موضع مرئي على ارتفاعات الشاشات القصيرة. بعد النقر، يتحول إلى حالة معالجة واحدة مثل «جارٍ التحقق…» ويُعطّل مؤقتًا لمنع الإرسال المتكرر. إذا فشل الدخول، يبقى اسم المستخدم في مكانه، وتظهر رسالة عامة آمنة لا تكشف وجود الحساب. إذا كان المستخدم يفضل تقليل الحركة، لا تظهر شاشة الهوية المتحركة أو تظهر مباشرة بشكل ثابت.

## 2. هيكل موحد للوحة الرئيسية

كل لوحة رئيسية تستخدم نفس الهيكل، لكن محتواها يتغير حسب الدور. هذا يقلل تكاليف التعلم، ويمنع تصميم شاشة جديدة لكل وظيفة.

```text
┌──────────────────────────────────────────────────────────────────┐
│ صباح الخير، [الاسم] · [الدور]                 [بحث] [تنبيهات]   │
├──────────────────────────────────────────────────────────────────┤
│ حالة تحتاج قرارًا الآن / لا توجد إجراءات حرجة                    │
├───────────────────────────────┬──────────────────────────────────┤
│ المهمة التالية                 │ 3 مؤشرات مرتبطة بالدور فقط       │
│ [زر الإجراء الأساسي]          │ [مؤشر] [مؤشر] [مؤشر]             │
├───────────────────────────────┴──────────────────────────────────┤
│ مهامي اليوم: 3 صفوف قابلة للتنفيذ مباشرة                         │
├──────────────────────────────────────────────────────────────────┤
│ مساحات العمل: 4 اختصارات كحد أقصى + «كل الأقسام»                │
└──────────────────────────────────────────────────────────────────┘
```

### قواعد العرض

| العنصر | القاعدة |
|---|---|
| شريط الحالة | يُظهر حالة واحدة ذات صلة: إجراء عاجل، أو رسالة استقرار. لا تكرر التنبيهات نفسها في أكثر من مكان. |
| مؤشرات الأداء | ثلاثة فقط. كل مؤشر قابل للنقر ويقود إلى قائمة مفلترة، لا إلى لوحة عامة. |
| المهمة التالية | إجراء واحد ذهبي؛ يُشتق من أعلى أولوية تشغيلية مسموحة للمستخدم. |
| قائمة المهام | ثلاثة عناصر كحد أقصى، مع حالة واضحة وموعد أو سبب الإجراء. |
| مساحات العمل | أربع وجهات شائعة للدور؛ بقية الوحدات عبر البحث أو «كل الأقسام». |
| التنقل الجانبي | يبقى موجودًا، لكنه يبدأ بمجموعتي «عملي اليوم» و«كل الأقسام»، بدلاً من فتح كل المجموعات. |
| الجوال | تتحول المؤشرات إلى صف قابل للتمرير، ويظهر زر المهمة التالية ثابتًا في أسفل الصفحة عند الحاجة. |

## 3. إعدادات اللوحة حسب الدور

التطبيق يدعم حاليًا الأدوار: `admin` و`branch_manager` و`data_entry` و`operations` و`maintenance` و`finance` و`viewer` و`kiosk`.[1] المقترح التالي يستخدم هذه الأدوار كما هي، ولا يضيف دورًا أو صلاحية جديدة.

| الدور | الهدف عند فتح النظام | الإجراء الرئيسي | المؤشرات الثلاثة | مساحات العمل الظاهرة أولًا |
|---|---|---|---|---|
| **المدير** | اتخاذ قرار ومتابعة الاستثناءات | مراجعة الإجراءات الحرجة | تنبيهات مفتوحة، جاهزية الأسطول، التزام الوثائق | لوحة المدير، مؤشرات الأداء، التحليلات، تقرير الأداء |
| **مدير الفرع** | إدارة خطة الفرع اليومية | فتح خطة اليوم | رحلات اليوم، مركبات نشطة، تنبيهات حرجة | الجدول، التتبع، الساحات، التسليم والاستلام |
| **العمليات** | توزيع الحركة وحل الاستثناءات | فتح جدول اليوم | رحلات غير مخصصة، تأخيرات، مركبات متاحة | الجدول، النقل، التتبع الحي، الساحات |
| **الصيانة** | تنفيذ أولويات الورشة | فتح أوامر الورشة العاجلة | أوامر مفتوحة، مركبات خارج الخدمة، قطع منخفضة | الورشة، المحروقات، قطع الغيار، الإطارات والبطاريات |
| **المالية** | معالجة المعاملات بانتظار الإجراء | مراجعة المعاملات المعلقة | فواتير بانتظار مراجعة، طلبات شراء، عهد مفتوحة | المشتريات، العهد، الفواتير، السجلات |
| **إدخال البيانات** | رفع جودة السجل التشغيلي | معالجة أخطاء جودة البيانات | سجلات ناقصة، وثائق ناقصة، تعيينات غير مكتملة | الموظفون، المركبات، ربط السائق، جودة البيانات |
| **المشاهد** | معرفة الحالة بدون خطر تعديل | فتح ملخص الحالة | الجاهزية، التنبيهات، حركة اليوم | لوحة الأسطول، مؤشرات الأداء، التحليلات، السجلات المسموحة |
| **الكشك** | تنفيذ معاملة ميدانية واحدة بسرعة | بدء النقل أو تسجيل دخول/خروج | حالة الرحلة، المركبة أو الساحة، آخر إجراء | تطبيق النقل، الساحة، مساعدة قصيرة، تسجيل الخروج |

## 4. تفاصيل أهم ثلاث لوحات

### لوحة العمليات

يفتح المستخدم على «خطة اليوم»، وليس رسمًا بيانيًا عامًا. تظهر أعلى الصفحة رسالة مثل «لديك 3 رحلات تحتاج تخصيصًا»، مع زر واحد: **تخصيص الرحلات**. تعرض المؤشرات: رحلات غير مخصصة، مركبات متاحة، وتنبيهات تأخير. تحتها تظهر قائمة من ثلاث رحلات فقط، وتحتوي كل رحلة على وجهة واحدة مفيدة مثل «تخصيص سائق» أو «فتح التتبع».

### لوحة الصيانة

يبدأ المستخدم بـ «أولوية الورشة». الإجراء الأساسي هو **عرض أوامر العمل العاجلة**. المؤشرات تقتصر على: المركبات خارج الخدمة، أوامر العمل المفتوحة، وقطع الغيار المنخفضة. لا تظهر بيانات الجدولة أو المالية إلا عند الانتقال المقصود إليها. تجعل هذه الشاشة الحالة الفنية قابلة للمعالجة بدل أن تكون تقريرًا كثيفًا.

### لوحة المالية

تبدأ الصفحة بصف انتظار واضح: «معاملات تحتاج مراجعتك». يكون الإجراء الأساسي **مراجعة المعاملات المعلقة**. تعرض المؤشرات: عدد الفواتير، أوامر الشراء، والعهد المفتوحة. تحتوي قائمة المهام على ثلاثة صفوف فقط: أعلى معاملة قيمة، أقدم معاملة، ومعاملة ناقصة وثيقة. لا ينبغي أن تظهر بيانات GPS أو الورشة في هذه الشاشة الأولى.

## 5. قائمة جانبية أبسط

القائمة الحالية غنية بالوحدات، وهي ضرورية للوصول الكامل لكنها ليست مثالية للبدء اليومي.[2] تُبقي النسخة المقترحة كل الروابط، لكنها تغير العرض الأولي.

| المجموعة | الظاهر أولًا | ملاحظات |
|---|---|---|
| عملي اليوم | الإجراء الأساسي، الجدول، التنبيهات، بحث الأقسام | تتغير الروابط بحسب الدور. |
| مساحات العمل | أربع روابط خاصة بالدور | يمكن فتح «كل الأقسام» عند الحاجة. |
| الإدارة | تظهر للمدير فقط | تضم المستخدمين، الإعدادات، التدقيق، الأداء. |
| كل الأقسام | المجموعات الحالية نفسها | تبدأ مطوية ولا تُحذف من النظام. |

لا يُقترح إخفاء مسار مسموح به اعتمادًا على التصميم فقط. يجب أن يبقى فحص الصلاحيات في الخادم هو مصدر الحقيقة، بينما تعمل القائمة المبسطة كترتيب بصري للوصول المتكرر.

## 6. منطق التخصيص المقترح

يُفضل تعريف إعداد واجهة ثابت على الخادم، مثل `ROLE_HOME_CONFIG`، بحيث يربط كل دور بعنوان اللوحة، والإجراء الأساسي، وثلاثة مؤشرات، وأربع وجهات. لا يُسمح للمستخدم بتغيير إعداد دور آخر من الواجهة. يمكن للإدارة لاحقًا تخصيص الوجهات المفضلة داخل الحدود المصرح بها فقط.

```python
ROLE_HOME_CONFIG = {
    "operations": {
        "title": "خطة الحركة اليوم",
        "primary_action": {"label": "تخصيص الرحلات", "href": "/schedule"},
        "workspaces": ["/schedule", "/schedule/transport", "/tracking", "/yard"],
    },
    "maintenance": {
        "title": "أولوية الورشة",
        "primary_action": {"label": "فتح أوامر العمل", "href": "/workshop"},
        "workspaces": ["/workshop", "/fuel", "/spare_parts", "/inventory/tires"],
    },
}
```

تستبدل القيم أعلاه برقم أو حالة حقيقية من مصادر النظام الحالية. إذا تعذر تحميل مصدر مؤشر، تظهر بطاقة بحالة «غير متاح الآن» مع رابط بديل، ولا تُعرض قيمة صفرية مضللة.

## 7. القياس قبل تعميم التصميم

تُقاس النسخة الجديدة بحسب الدور، لا بمؤشر إجمالي واحد. تضاف أحداث محدودة غير شخصية: `role_home_view` و`primary_action_click` و`task_opened` و`workspace_opened` و`task_completed`. ثم تُقارن ثلاثة مقاييس خلال فترة متفق عليها.

| المقياس | التعريف | علامة النجاح |
|---|---|---|
| زمن الوصول للمهمة | من عرض اللوحة إلى فتح المسار التشغيلي | انخفاض الزمن لكل دور مقارنة باللوحة الموحدة |
| نسبة استخدام الإجراء الرئيسي | `primary_action_click ÷ role_home_view` | ارتفاع الاستخدام عندما تكون المهمة صحيحة للدور |
| إكمال المهمة | حدث إكمال العمل بعد فتح المهمة | عدم ارتفاع النقرات على حساب الإكمال الحقيقي |

يجب تجنب اعتبار زيادة النقرات نجاحًا تلقائيًا. النجاح هو أن يصل المستخدم إلى العمل الصحيح بسرعة ويكمله دون العودة أو تكرار المحاولة.

## 8. تسلسل التنفيذ

| المرحلة | التغيير | المخاطر | الاختبار |
|---|---|---|---|
| 1 | بناء إعدادات `ROLE_HOME_CONFIG` وعرضها فقط للمسارات الحالية | منخفضة، لأن الصلاحيات لا تتغير | اختبار كل دور ومسار ظاهر |
| 2 | تحويل الصفحة الرئيسية إلى مكونات: حالة، إجراء، ثلاثة مؤشرات، مهام، مساحات | متوسطة بصريًا | اختبار الجوال والكمبيوتر لكل دور |
| 3 | تقليل القائمة الافتراضية مع الاحتفاظ بـ «كل الأقسام» | منخفضة وقابلة للعكس | التحقق من الوصول إلى الروابط الحالية |
| 4 | قياس الاستخدام ومقارنة الإكمال | لا تغيير في سير العمل | مراجعة نتائج كل دور بعد فترة تشغيل |

## القرار المقترح

يُعتمد هذا التصميم على مرحلتين. تبدأ المرحلة الأولى بدور **العمليات** لأنه يملك رحلة يومية واضحة ويمكن قياسها: فتح جدول اليوم، تخصيص رحلة، ثم متابعة التنفيذ. بعد نجاح المقاييس، تُطبق البنية نفسها على الصيانة والمالية وإدخال البيانات. يحافظ هذا التسلسل على قابلية التراجع ويمنع إعادة تصميم كل النظام دفعة واحدة.
