# الوكيل الهندسي الذاتي — Bin Zomah

## الغرض والنطاق

أضيفت أداة تطوير محلية مستقلة عن Flask وتطبيق الإنتاج. تنفذ دورة محدودة: **فهم المشروع → تخطيط المهام → اختيار النموذج → اقتراح patch → التحقق من السلامة → الفحوص المتوازية → الإصلاح/إعادة المحاولة → التراجع عند الفشل → حفظ ملخص ذاكرة**.

لا تُسجّل الأداة كـ Flask route، ولا تعمل مع بدء الخادم، ولا تتصل بقاعدة بيانات التطبيق. لا تنفذ نشرًا أو التزامًا أو دفعًا إلى GitHub.

## ما يقابل المواصفة

| الطبقة | التنفيذ الحالي |
|---|---|
| توجيه النماذج | يختار ملفًا سريعًا أو استدلاليًا بحسب التعقيد والمخاطر وحجم السياق والدقة المطلوبة. الاسمان قابلان للضبط بمتغيرات البيئة. |
| فهم المشروع | خريطة للملفات النصية والوحدات والاعتماديات والمسارات والاختبارات وملفات CI والترحيلات. يستبعد قواعد البيانات والملفات المحلية والأسرار. |
| التخطيط | يقبل خطة JSON بمهام مترابطة ويتحقق من الاعتماديات والدورات؛ المهام المستقلة تظهر في مستويات قابلة للتوازي. |
| التنفيذ المتوازي | تحليل الخريطة ومسح الأسرار والترحيلات والفحوص المستقلة تعمل بالتوازي. تطبيق التغييرات يبقى تسلسليًا لتفادي تعارض الملفات. |
| الإصلاح الذاتي | يعيد طلب patch بعد فشل التحقق بحد أقصى 3 محاولات. |
| نقاط الاستعادة | يشترط مجلد عمل نظيف، ينشئ فرعًا محليًا إذا كان الفرع `main`/`master`، ويلتقط نسخة من الملفات المستهدفة. يعيد الملفات المتغيرة إلى checkpoint إذا فشلت الفحوص. |
| الاختبار | فحوص allowlist: `compile`, `unit`, `security`, `migrations`, `performance`. لا تقبل أوامر shell من النموذج. |
| الأمان | حجب ملفات الأسرار والبيانات، تنقيح قيم مفاتيح محتملة من سياق النموذج، رفض المسارات خارج المستودع والروابط الرمزية والحذف/إعادة التسمية والملفات الثنائية. |
| قاعدة البيانات | فحص ساكن لكلمات `DROP`, `TRUNCATE`, و`DELETE` غير المحدود؛ لا تُنفذ migrations أو تغييرات على قاعدة بيانات. |
| الأداء | تسجل أزمنة مراحل الفحص في التقرير والذاكرة؛ قياس أداء التطبيق يحتاج benchmark خاصًا قبل/بعد لم يُهيأ بعد. |
| الذاكرة | ملخص محلي في `.agent-memory/history.json` يتضمن بصمة الهدف والملفات والحالة وأزمنة الفحوص، ولا يحفظ نص الهدف أو مفاتيح API. |
| Git | حماية الفرع وحالة العمل؛ لا `commit` ولا `push` ولا `force push`. |
| الاستمرارية | حلقة محدودة لهدف واحد، بحد أقصى 3 محاولات، وليست خدمة أو daemon تعمل بلا نهاية. |

## التشغيل

من جذر المستودع:

```bash
python -m tools.engineering_agent --root . inspect
```

للتنفيذ الفعلي يلزم ضبط `GEMINI_API_KEY` في بيئة المطور فقط:

```bash
export GEMINI_API_KEY='...'
python -m tools.engineering_agent --root . run --task "إصلاح المشكلة المحددة وإضافة اختبار لها"
```

الملفات الحساسة تتطلب إذنًا صريحًا لكل تشغيل:

```bash
python -m tools.engineering_agent --root . run --task "..." --allow-sensitive
```

متغيرات التوجيه الاختيارية:

- `ENGINEERING_FAST_MODEL` — الافتراضي `gemini-2.5-flash`.
- `ENGINEERING_REASONING_MODEL` — الافتراضي `gemini-2.5-pro`.

لا تحفظ المفتاح في المستودع. عند تشغيل `run` تُرسل خريطة المشروع ثم محتوى الملفات المخططة (بعد تنقيح قيم الأسرار) إلى Gemini؛ لا يحدث أي اتصال خارجي عند `inspect`.

## حدود الحماية

- لا تعديل على `app.py`، المصادقة/الأمان، `migrations/`، `.github/`، ملفات الاعتماديات أو النشر، إلا مع `--allow-sensitive`.
- يُرفض العمل عند وجود تعديلات محلية غير محفوظة كي لا يختلط checkpoint بتغييرات المطور.
- التعديلات على الملفات الحساسة، حذف الملفات، إعادة تسميتها، البيانات الإنتاجية، أو أوامر النشر وقاعدة البيانات ليست ضمن التنفيذ الذاتي.
- الفحوص المحلية لا ترث مفاتيح API أو البريد أو اتصال قاعدة بيانات إنتاجية.
- «الفحص الأمني» في هذه النسخة مسح ساكن أولي للأسرار والعمليات المدمرة، وليس بديلًا عن مراجعة أمنية مستقلة أو فحص ثغرات الاعتماديات.

## التحقق

الاختبارات: `tests/test_engineering_agent.py` تغطي اختيار النموذج، ترتيب المهام، منع المسارات الخطرة، تدقيق patch، رصد الأسرار/العمليات المدمرة، والتراجع. تشغيل الأداة اختياري بالكامل ولا يؤثر في خادم التطبيق.
