# تنبيهات تجاوز السرعة حسب نوع المركبة

يضيف النظام فحصاً دورياً كل خمس دقائق عبر GitHub Actions، ويستدعي endpoint محمياً في التطبيق. لا يخرج `GPS_TOKEN` من بيئة الخادم، ولا تقبل واجهة الفحص أي توكن GPS من العميل.

## الحدود المعتمدة

| الفئة | الحد |
|---|---:|
| الشاحنات | 80 كم/س |
| السيارات الخفيفة | 120 كم/س |
| الحافلات | 90 كم/س |

يتم تجاهل قراءة GPS القديمة التي يزيد عمرها عن ثلاث دقائق، وتُنشأ رسالة جديدة عند بداية التجاوز فقط. تستمر الحالة النشطة دون تكرار الرسائل إلى أن تعود المركبة إلى الحد أو تختفي القراءة الحديثة.

## إعداد البيئة

يجب إضافة `ALERT_CRON_KEY` إلى متغيرات Runtime في 509 Cloud، ثم إضافة السر نفسه إلى GitHub Actions باسم `ALERT_CRON_KEY`. كما يجب إضافة السر `LIVE_APP_URL` بقيمة `https://invoice-bin-zoma.509.rip` إلى GitHub Actions. لا تضع أيّاً من هذه القيم داخل ملفات المشروع.

بعد إضافة الأسرار، يمكن تشغيل Workflow يدوياً من تبويب Actions للتحقق من أول فحص. يعمل الجدول تلقائياً كل خمس دقائق، وتظهر التنبيهات المحفوظة للمستخدم المصرح له عبر `GET /api/speed-alerts`.

## قنوات الإشعار

إذا كانت اشتراكات Web Push ومفاتيح VAPID مضبوطة، يرسل النظام إشعار Push عند بداية التجاوز. حتى عند عدم ضبط Push، تُحفظ الحوادث في سجل التنبيهات، وتبقى استجابة مهمة الفحص مقتصرة على عدد التنبيهات الجديدة دون كشف بيانات حساسة.
